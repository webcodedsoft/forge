## Working in Forge

This app is built by the Forge agent for our team. It runs in a sandbox container.

- The dev server is already running on port 3000 with hot reload. Do not start, stop or restart it, and do not run `next build` to check your work; run `pnpm typecheck` and `pnpm lint` instead.
- Use `pnpm` for packages. Add dependencies with `pnpm add <pkg>`; never edit `node_modules`.
- Stack: Next.js App Router (`src/app`), React Server Components by default, Tailwind CSS v4. Add `"use client"` only where interactivity needs it.
- Icons come from `lucide-react` (already installed; browse at https://lucide.dev/icons or https://www.shadcn.io/icons). Never use emoji, icon fonts or hand-drawn SVGs as UI icons; icon-only buttons need an `aria-label`.
- Keep the app working after every change. Prefer small, focused edits over rewriting whole files.
- Never commit secrets. Configuration that needs secrets reads from environment variables.
- Do not run `git commit`, `git push` or rewrite history; Forge commits your work after each run.

## Project structure

Keep code organised so teammates (and the agent) can find and reuse things:

- `src/app/` routes: pages and layouts compose components and pass data; no large blocks of UI or logic inline.
- `src/components/` reusable UI (one component per file, typed props); `src/components/ui/` small primitives (Button, Card, Badge, EmptyState).
- `src/lib/` data access, API calls, mapping, formatting, validation and business logic (no JSX).
- `src/hooks/` client hooks (`useSomething`), e.g. data loading or UI state shared by several components.
- `src/types/` shared types (or a `types.ts` next to the feature).
- Extract a component when UI repeats or a file passes ~200 lines; don't create wrappers or helpers that are used once.

## Our API (data)

Apps get their data from our in-house REST API, never from a local database.

- The API connections enabled for this project are described in `.forge/apis/README.md`, with the full OpenAPI spec next to it. Read that file before building anything that shows or changes data. If it does not exist, the project has no API connection yet: tell the user to enable one in Forge (Project → APIs) instead of inventing endpoints or mock data.
- Call the API only through the generated typed clients in `src/lib/forge-api/` (they use openapi-fetch). Client components use `<name>Api` from `@/lib/forge-api/<name>`; Server Components and route handlers use `await <name>ServerApi()` from `@/lib/forge-api/<name>.server`.
- Requests go through this app's route `/api/forge/<name>/...`, which adds the signed-in user's token. Never put tokens or secrets in browser code, and never call the API's URL directly from the browser.
- Files marked "Generated by Forge" are regenerated from the spec; do not edit them.
- Handle loading, empty and error states for every API call; a 401 or 403 means the user is not allowed to see that data.
